达人投放的难点，不只是缺少数据

需求、决策、内容和复盘分散在不同角色与系统中，任何一个口径没有对齐，都会变成执行阶段的返工。

从“凭经验选人”到“用证据做决定”，中间缺少的是一条能被团队共同理解和执行的业务链路。

判断依据

达人组合依赖人工经验

粉丝量、垂类、人群、历史转化与履约表现散落在不同表格里，推荐理由很难复用。

协作口径

预算和目标容易反复确认

“5万元是否包含投流”会直接改变达人数量与效果预估，模糊口径会让后续方案失真。

结果闭环

投后报表没有变成任务

团队能看到曝光和订单，却未必知道问题属于达人、内容还是门店，也缺少明确责任人。

四类角色，在同一个 Campaign 上协作

Agent 负责连接信息与生成建议；关键业务动作仍由对应角色确认。

项目经理确认目标、预算和方案
达人运营筛选达人、协调档期
内容审核校验脚本与品牌规则
数据运营分析效果与门店差异

让 Agent 沿着业务阶段工作，而不是停在聊天框里

每一步都产生可解释的业务输出，并在进入下一阶段前保留人工控制点。

需求澄清

主动追问预算是否包含投流，把业务语言转换为可执行约束。

输出：Campaign简报

达人方案

综合转化、人群、垂类、内容、履约和成本，生成三套风险收益策略。

输出：均衡型组合

内容审核

生成45秒脚本，支持编辑、版本锁定和人工审核，不由 Agent 自动发布。

输出：审核脚本版本

投后复盘

分析达人、内容和门店表现，区分数据事实与待验证推断并生成任务。

输出：优化任务看板

四个设计判断，决定 Agent 是否值得信任

智能不是替用户做完所有决定，而是在正确的时点提供证据、边界和下一步。

先追问，再推荐

预算口径没有确认时暂停生成，避免用错误约束计算方案。

推荐必须可解释

同时展示评分权重、风险区间、替换理由和不完整数据边界。

关键动作由人确认

方案写入、脚本审核和任务创建都保留明确人工控制点。

事实与推断分层

模型不能把内容问题的猜测包装成已被业务数据证明的结论。
